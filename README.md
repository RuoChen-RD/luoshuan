# 螺栓已拧 ROI 检测原型

这是一个固定相机、固定点位的浏览器原型。打开 `index.html` 后会加载 `assets/sample-board.png`，并以这张图的像素坐标作为标准 ROI 点位；蓝色或金属垫片不算螺栓，只有检测到上方黑色螺栓头才判定为已拧上。

## 使用方式

1. 直接用浏览器打开 `index.html`。
2. 点击“重新检测”查看当前样图结果。
3. 如果圈仍有轻微偏移，点击“按当前图校准点位”，系统会在当前固定点位附近吸附圆心。
4. 勾选“编辑点位”后，在图片上拖动 ROI 圆圈微调坐标。
5. 右侧可修改点位编号、坐标、半径和检测目标。
6. 点击“应用修改”或拖动结束后，点位会自动保存到浏览器本地，刷新页面仍会保留。
7. 导入新图片时，图片需要和 `sample-board.png` 保持同机位、同角度、同分辨率；系统会按固定坐标直接检测。
8. 点击“保存点位文件”可把当前点位写入 `bolt-layout.json`。
9. 点击“打开点位文件”可读取之前保存的点位 JSON，并继续编辑。
10. 点击“恢复默认”可清除本地保存的点位，回到内置点位。
11. 点击“导出结果”保存本次检测结果 JSON。
12. 点击“导入录像”或“打开摄像头”后，可点击“开始监控”进入视频模式。
13. 点击开始监控时会锁定当前“未拧”清单；后续枪头只在这份清单中匹配，同一点位连续稳定且连续检测到绿灯 OK 后，才把该点从“未拧”改为“已拧”。
14. 如果导入的是松开螺丝视频，请把“作业模式”切到“松开测试”，系统会实时检测灯号和枪头，但不会写入拧紧 OK。

注意：`file://` 打开和 `http://` 打开使用的是不同的浏览器本地存储空间。现场调试时建议固定使用同一种打开方式。

如果浏览器支持 File System Access API，页面会直接写入你选择的 JSON 文件；如果不支持，会自动退回为下载 JSON 文件。

## YOLOv8 关键点升级

当前规则算法可以继续用于没有模型时的基础检测；要提高“枪头当前拧哪个点位”的准确率，项目已准备好 YOLOv8n-pose 训练管线。模型只训练一个类别 `screwdriver` 和一个关键点 `tip`（批头末端），不把 77 个螺丝编号训练成 77 个类别。模型输出的关键点再映射到固定 ROI，最后仍由绿灯状态机决定是否计数。

### 你需要准备什么

1. 提供更多实际拧紧视频，建议至少 3 到 5 段，覆盖不同点位、枪体倾斜、手遮挡、红灯/绿灯、运动模糊和不同光照。现有 `assets/拧紧.mp4` 可作为第一段素材。
2. 安装训练依赖：`python3 -m pip install -r requirements-training.txt`。
3. 抽取待标注帧：`python3 scripts/extract_pose_frames.py assets/拧紧.mp4 --sample-fps 2`。
4. 使用 CVAT、Label Studio 或 Roboflow 标注每个画面中的拧紧枪。每个实例画一个包含枪体的框，并把 `tip` 点放在真正接触螺丝的批头末端；枪头被完全遮挡的帧可以不标注或作为负样本。
5. 导出为 YOLO pose 格式，将图片放入 `training/dataset/images/train` 或 `val`，对应标签放入同名的 `labels/train` 或 `val`。每行格式为：`class cx cy w h tip_x tip_y visibility`，所有坐标归一化到 0 到 1，`class` 固定为 `0`，`visibility` 使用 `2`（可见）、`1`（遮挡但位置可判断）或 `0`（不可见）。
6. 运行 `python3 scripts/validate_pose_labels.py` 检查数据，再运行 `python3 scripts/train_tip_pose.py --device mps` 训练。
7. 用 `python3 scripts/export_tip_pose.py training/runs/screwdriver-tip-yolov8n/weights/best.pt` 导出 `training/models/screwdriver-tip.onnx`，再进行网页推理接入。

建议第一批至少准备 800 张已标注帧，其中 20% 留作验证集；不要把同一视频的相邻帧随机混到训练集和验证集，否则准确率会虚高。你只需要负责提供视频和标注，训练脚本、标签校验和 ONNX 导出脚本已经放在项目中。

## 现场落地流程

1. 固定相机、镜头、曝光、白平衡和光源。
2. 以 `sample-board.png` 为标准图，标定所有孔位/垫片中心的 ROI。
3. 后续图片/视频必须保持同一拍摄位置和角度；如果分辨率不同，系统会按 `sample-board.png` 的 1920x1080 标准坐标等比缩放 ROI。
4. 所有点位默认都参与检测，垫片位置没有黑色螺栓头时判定为未拧。
5. 先用规则阈值跑一批真实图片，统计误判点。
6. 优先调整“最小黑色占比”“最小深黑占比”和 ROI 中心位置；当前算法会识别白色/蓝色垫片，只有垫片但深黑螺栓头不足时判为未拧。

## 判断逻辑

- `已拧`：ROI 中心核心区检测到足够的黑色螺栓头。
- `复核`：检测到黑色区域，但信号偏弱、面积过大或位置偏心，可能是污渍、反光、拧偏或 ROI 未对准。
- `未拧`：中心核心区黑色螺栓头占比过低，或垫片占比很高但没有足够深黑螺栓头。
- `忽略`：人工跳过该 ROI，不参与检测。
- `拧紧枪OK`：视频模式下，画面检测到拧紧枪绿灯，并且枪头靠近某个固定 ROI，该点位会记录绿灯确认。

单个俯视相机只能做贴合的间接判断。若贴合高度要求严格，建议增加低角度侧光、侧相机或激光测高；当前原型适合作为第一阶段的固定坐标 ROI 检测。

## 视频监控方案

当前实现是规则版视频监控，不依赖 AI 模型。每一帧会执行三件事：

1. 按固定坐标检测 77 个 ROI，判断是否有黑色螺栓头。
2. 在画面上半部分检测高亮绿灯、红灯或黄灯，绿灯作为拧紧枪 OK 信号。
3. 根据灯号位置或枪杆连续性跟踪枪身方向，利用枪头下方不再延伸的特征定位批头末端；枪头坐标独立识别，计数时再严格校验它是否属于开始监控时锁定的“未拧”清单。

为避免手、枪身或灯光闪烁造成误计数，枪头点位需连续两帧一致，绿灯也需连续两帧出现；枪头被手短暂遮挡时只保留约 1 秒的最近稳定点位。只有初始状态为“未拧”的点能发生一次 `未拧 -> 已拧` 转换。松开测试模式完全不改变计数。

最终建议按组合结果判断：`固定 ROI 检测已装` + `拧紧枪绿灯OK`。手、枪身和批头会遮挡画面，所以被遮挡的瞬间不适合只靠螺栓外观判断，绿灯事件和后续无遮挡帧更可靠。

## 误判处理

如果已拧点大量显示为复核，通常是螺栓头高光导致黑色区域偏到一侧，可以适当降低“最小黑色占比”或放宽“最大偏心”。如果只有白色/蓝色垫片的位置显示为已拧，说明深黑头信号阈值过松，应提高“最小深黑占比”；当前默认值为 `0.16`，并额外加入了“垫片占比高但深黑螺栓头不足”时直接判未拧的规则。
